# ТЗ: Watermark bot для MAX (v1)

**Статус:** функциональность v1 в коде закрыта (меню, шаблоны, хвосты, личка, альбомы, каналы, профиль-заглушка). Приёмка §9 на телефоне MAX — человеком с `MAX_TOKEN`. Локальная БД — Postgres в **OrbStack** (`docker compose`, хост-порт 5433). Git remote / публикация / биллинг — не в этом этапе.

Бот вешает водяной знак на фото/видео в личке и в каналах. Меню — как в `answer`: inline-клавиатуры MAX, без дублей, «Назад» возвращает туда, откуда пришли. Подписка и оплата — не в этом этапе.

Репозиторий: `/Users/a/Desktop/max/watermarkbot`. Скриншоты Telegram/мини-аппа — карта функций, не целевой UI. Мини-апп и «Open editor» — после v1.

## 1. Что входит / что нет

**Входит (сделано)**

- Личка: юзер кидает фото или видео (альбом — каждое вложение) → бот отвечает файлом с водяным знаком (дефолтный шаблон). Подпись результата: «Готово». Оригинал не пересылается обратно.
- Документ-картинка (`file` + magic PNG/JPEG/WebP/GIF/BMP, плюс то, что открывает Pillow) обрабатывается как фото.
- Стикер / аудио / контакт / локация → «этот тип не поддерживается».
- Шаблоны водяных знаков: создать (прислать картинку или файл), список с превью-полотном, карточка, дефолт, удалить, параметры (позиция, ширина, прозрачность, поворот, сдвиг X/Y).
- Видеохвостики: короткий ролик в начало или конец; опция «Не использовать». Лимит длины — `MAX_TAIL_SECONDS` (по умолчанию 15 с).
- Каналы: бот админом, привязка форвардом поста, авто-наложение, выбор шаблона («как в личке» или конкретный), хвост вкл/выкл, выключить авто, отвязать. Успешный пост **заменяется**: в канал уходят все обработанные фото/видео без подписи «Готово», оригинал удаляется, если все вложения ушли.
- Профиль: id, имя, «Тариф: демо», счётчики за день (фото/видео/трафик). Без кнопок оплаты.

**Не входит (потом)**

- Оплата, звёзды, рефералка, «мои боты», hosted-токены.
- Мини-апп, визуальный редактор, светлая/тёмная тема.
- Motion-анимация знака (кнопки в меню нет, пока не будет экрана).
- Лимиты и paywall. Константы длины видео/хвоста в конфиге есть, квоты на пользователя нет.
- Очередь джоб / отдельный ffmpeg-воркер / 5xx-ретраи MAX. Обработка в том же процессе uvicorn.
- GitHub / прод-деплой (k3s). Локально: OrbStack + `docker compose` (bot + Postgres).

## 2. Правила меню (списано с `answer`)

Источник паттернов: `answer` (`btn`, in-place edit, WAIT, disable_link_preview). Не копипаста монолита.

1. **Один экран = одно сообщение.** Текст правим in-place (`PUT /messages`). Фото-экран нельзя собрать через PUT → delete-then-send. Не плодить пузыри на MAX mobile.
2. **«Назад» с пикера** ведёт на карточку шаблона (`tpl:open:{id}`), не на `/start`. Пикеры открываются только с карточки, отдельный origin-код в payload не нужен.
3. **Без дублей.** На экране нет двух кнопок с одним действием. Корневые вкладки не повторяются на пикерах.
4. **Футер вкладок только на корнях разделов и карточках разделов**, не на пикерах (сетка + «← Назад»).
5. **Любой подэкран имеет ровно одну «← Назад».**
6. **Кнопки** — `{"type":"callback","text","payload"}`. Payload короткий, двоеточия (`tab:tpl`, `wm:setpos:9:se`). Подписи русские, в билдерах.
7. **Клавиатуры — чистые функции.** БД в хендлере, в билдер передаются модели (`Template`, `Tail`, `Channel`).

Корень — четыре вкладки:

```
Шаблоны | Хвосты
Каналы  | Профиль
```

Активная вкладка с галкой в тексте кнопки.

Callback ACK — в роутере, до отрисовки (крутилка MAX не зависает, даже если хендлер ничего не показал). `/start` снимает текущий WAIT и открывает Шаблоны.

## 3. Карта экранов v1

### 3.1 Шаблоны (корень)

Текст: коротко, что нажать. Если шаблоны есть — одно превью-полотно (контакт-лист миниатюр), не альбом.

Клавиатура:

- на каждый шаблон ряд: `✓ N` (сделать дефолтом / уже дефолт) | `✎ N` (карточка)
- `+ Новый`
- футер вкладок

Пустой список: «Нет шаблонов» + `+ Новый` + футер. Без фейковой карточки.

**+ Новый:** «Пришлите картинку водяного знака (лучше PNG с прозрачностью)», `WAIT_WM_IMAGE`. «❌ Отмена» → список. Пришла картинка/файл-картинка → шаблон создан (имя из файла, иначе «Шаблон N»), дефолтные параметры, открывается карточка. Первый шаблон пользователя становится дефолтным.

### 3.2 Карточка шаблона

Фото: превью — знак наложен на пластину, не сырой PNG.

Текст: расположение, ширина %, прозрачность %, поворот, отступ X/Y.

```
Расположение | Ширина
Прозрачность | Поворот
Сдвиг по X   | Сдвиг по Y
✓ В работе   | Удалить     (или «Сделать основным»)
← Назад
```

«Назад» → список шаблонов. Футер вкладок — да.

Удалить → «Удалить? / Отмена», после удаления — список. Если удалили дефолт — дефолтом становится следующий по id или никого.

### 3.3 Пикеры (без футера)

| Экран | Варианты | Назад |
|---|---|---|
| Расположение | сетка 3×3, Случайно, По углам, Залить | карточка |
| Ширина | 5 / 10 / 15 / 20 / 25 / 30 / 40 / 50 / 60 / 75 / 100 % | карточка |
| Прозрачность | 20 / 40 / 60 / 80 / 100 % | карточка |
| Поворот | 0 / 90 / 180 / 270 / −15 / +15 | карточка |
| Сдвиг X / Y | −20 / −10 / 0 / +10 / +20 (% кадра) | карточка |

После выбора — сразу карточка с новым превью.

«По углам» = один знак во все четыре угла. «Залить» = растянуть на кадр (игнор % ширины). «Случайно» = случайная клетка сетки на каждом наложении.

### 3.4 Хвосты (корень)

Текст: «Видеохвостик — короткий ролик, добавляемый в начале или в конце основного видео.»

- `✓ Не использовать` (дефолт для лички)
- `+ Новый видеохвостик`
- список: `✓ имя` | `✎`
- пусто: «Нет видеохостиков»
- футер

**+ Новый:** `WAIT_TAIL_VIDEO` — «Пришлите короткий ролик — до 15 секунд.» Карточка: В начало / В конец, Сделать основным, Удалить, ← Назад. Нет duration у файла → отказ, не молчаливый пропуск лимита.

### 3.5 Каналы (корень)

Текст: `Всего: N`. Список привязанных каналов. Пусто: короткая инструкция (админ + «+ Канал» + форвард поста).

Карточка:

- Выключить / Включить авто
- Выключить / Включить хвост (флаг канала, не снимок id хвоста; при вкл берётся текущий дефолт пользователя)
- шаблон: «Как в личке» или номер шаблона
- Отвязать
- ← Назад + футер

Привязка: `WAIT_CHANNEL_FORWARD`. Форвард из канала, уже привязанного другим пользователем — отказ «Этот канал уже привязан», владельца не переписываем.

Авто: пост с фото/видео (альбом — каждое вложение) в привязанном канале с включённым авто → обработка по очереди → отправка в тот же чат отдельными сообщениями → удаление оригинала, **если ушли все** вложения. Повтор того же `mid` не обрабатывается (клейм в `processed_mids` до работы). Если **ни один** send не удался — клейм снимается. Если ушла часть — клейм остаётся, оригинал не удаляем (чтобы ретрай не повесил второй знак). Исходящий обработанный `mid` тоже помечается, чтобы бот не наложил знак сам на себя. Текстовые посты не трогаем. Поллинг обрабатывает апдейты последовательно; отдельного asyncio-lock на канал нет (семафор только на ffmpeg).

### 3.6 Профиль (корень, заглушка)

- имя, MAX id
- «Тариф: демо»
- сегодня: трафик, фото / видео
- только футер вкладок

### 3.7 /start и медиа в личке

`/start` → Шаблоны, WAIT сбрасывается (даже если ждали картинку/хвост/форвард).

Фото/видео в личке **вне** `WAIT_*`:

1. Нет шаблона → «Сначала добавьте водяной знак» + «К шаблонам».
2. Есть дефолт → «Обрабатываю…» / «Обрабатываю видео…», ответ файлом «Готово». Альбом — одно прогресс-сообщение, затем каждый файл с подписью «Готово».
3. Документ-картинка — как фото (суффикс png/jpg/… **или** файл без имени: magic через Pillow). Документ-видео (mp4/mov/webm/…) — как видео. Стикер, кружок (`video_note` / `is_round`), аудио, контакт, локация — «этот тип не поддерживается». 1 фото + 1 видео в одном посте — оба вложения, превью видео не выкидываем.

## 4. Стек

Как `answer`, без биллинга / tenants / miniapp / TG-моста.

| Слой | Выбор | Зачем |
|---|---|---|
| Язык | Python 3.12 | тот же, что `answer` |
| HTTP | FastAPI + uvicorn | webhook MAX; long-poll по умолчанию (`USE_WEBHOOK=false`) |
| MAX API | свой клиент (aiohttp), `platform-api2.max.ru` | один `send_message`, upload, edit/delete, answers |
| TLS | сертификаты Минцифры в образе | как у `answer` |
| БД | PostgreSQL + asyncpg, порт 5433 локально | без SQLite |
| Миграции | идемпотентный DDL на старте | `app/database/migrations.py` |
| Картинки | Pillow | RGBA overlay, JPEG на выход, контакт-лист |
| Видео | ffmpeg в thread + семафор (`FFMPEG_CONCURRENCY=1`) | overlay PNG на кадр, concat хвоста, h264+aac |
| Деплой v1 | OrbStack + `docker compose`: bot + postgres + volume `/data` | не Docker Desktop, k3s не нужен |
| Тесты | pytest | клавиатуры→ROUTES, канал-клейм, overlay, ffmpeg smoke |

Лимиты: `MAX_VIDEO_SECONDS=180`, `MAX_TAIL_SECONDS=15`. tmp после отправки удаляется.

Паттерны: `btn`, replace пузыря, `WAIT_*` (in-memory, TTL 15 мин), таблица callback `ROUTES`, `disable_link_preview`.

## 5. Данные

```
users(id, max_user_id unique, name, created_at)
templates(..., position, width_pct, opacity, rotation_deg, pad_x, pad_y, is_default)
  UNIQUE (user_id) WHERE is_default
tails(..., placement start|end, is_default)
  UNIQUE (user_id) WHERE is_default
user_settings(user_id, tails_enabled bool default false)   -- личка
channels(..., template_id null, tail_id null, use_tail bool default false, enabled)
  chat_id UNIQUE; template_id NULL = «как в личке»; use_tail = хвост канала вкл/выкл
jobs(..., kind photo|video, status, bytes_out)             -- профиль «сегодня»
processed_mids(chat_id, mid) PK                            -- клейм канала
```

`tail_id` в `channels` остаётся в DDL (на будущее pin конкретного хвоста), в v1 UI/логика использует `use_tail` + текущий дефолт.

Медиа на диске: `data/{user_pk}/...`, не в Postgres. В меню — «Шаблон N» или stem имени файла, обрезанный.

Домен в коде: frozen dataclass `User` / `Template` / `Tail` / `Channel` / `Overlay` / `DayStats`. Репозитории возвращают модели, не dict. PK пользователя и MAX id не смешиваются (`Screen.max_user_id`).

## 6. Наложение

Один RGBA-проход `render_overlay` для фото и видео (видео: PNG на размер кадра → `ffmpeg overlay=0:0`).

**Фото:** Pillow. Знак по `width_pct` ширины кадра, альфа × opacity, поворот, якорь 9 клеток + pad. «По углам» — четыре копии. «Залить» — resize на кадр. Выход JPEG.

**Видео:** тот же overlay; хвост — concat start/end, перекод h264+aac. Нет duration / duration ≤ 0 → ошибка, лимит не обходится нулём. Сырой stderr ffmpeg пользователю не показываем.

Личка: подпись «Готово». Канал: без этой подписи.

## 7. Архитектура процесса

```
MAX long-poll / webhook
  └─ dispatch(pool, update)
       ├─ bot_started / /start     → Шаблоны
       ├─ message_callback         → ACK, затем ROUTES[payload]
       └─ message_created
            ├─ chat_type=channel   → claim mid → process_media по каждому вложению → delete original
            ├─ WAIT_*              → ingest шаблона / хвоста / форварда (первое подходящее вложение)
            └─ photo|video|file    → process_media в личку (альбом — цикл)
```

Поллинг вызывает `dispatch` напрямую (без HTTP на себя), апдейты в пачке — по очереди. Вебхук — тот же `dispatch`. Старт без `MAX_TOKEN` или без `user_id` из `GET /me` — процесс не поднимается.

Канал:

1. Нет медиа / канал выкл / не привязан → выход.
2. `INSERT processed_mids` (уже есть → выход).
3. Для каждого вложения: скачать → `process_media` → пометить исходящий mid.
4. Ни один send не удался → снять клейм оригинала.
5. Хотя бы один send ок → клейм **не** снимаем. `DELETE` оригинала только если failed == 0 (если delete 403/не-ok — клейм остаётся, чтобы не зациклить знак; в канале могут остаться оригинал + обработанный, пока боту не дадут права на удаление).

Один процесс uvicorn. ffmpeg через `asyncio.to_thread` + семафор. Отдельный воркер — после v1, если упрёмся.

Ключевые модули:

| Путь | Роль |
|---|---|
| `app/handlers/dispatch.py` | вход апдейтов |
| `app/handlers/message_callback.py` | `ROUTES` |
| `app/handlers/message_created.py` | личка + WAIT |
| `app/handlers/channel.py` | авто канала |
| `app/handlers/pipeline.py` | `process_media` |
| `app/engine/image.py` / `video.py` | Pillow / ffmpeg |
| `app/api/max_api.py` | `send_message` / upload / delete→bool |
| `app/keyboards/builders.py` | клавиатуры |
| `app/renderers/views.py` | тексты экранов + `Screen` |

## 8. Оценка и факт

Первоначальная оценка (один человек, опыт MAX в `answer`): **12–16 рабочих дней** на v1; без видео 8–10; биллинг отдельно +5–8.

Факт: скелет, меню, фото, видео, хвосты, альбомы, каналы (замена оригинала + клейм), профиль-заглушка — в репозитории. Не закрыто для приёмки человеком: прогон §9 в клиенте MAX. Postgres локально — через OrbStack.

Главный продуктовый риск на смоуке тот же, что в `answer`: PUT vs delete-then-send на фото-меню в MAX mobile.

## 9. Приёмка v1

- `/start` открывает Шаблоны; футер ведёт в 4 корня без дублей.
- С любого пикера «← Назад» возвращает на карточку шаблона, не на `/start`.
- Фото в личке с дефолтным шаблоном → знак (позиция, %, прозрачность). Файл-картинка — то же.
- Видео в личке + хвост «в конце» (и хвосты включены) → ролик со знаком и хвостом.
- Пост с фото в привязанном канале → обработанный пост, оригинал удалён, тот же `mid` повторно не обрабатывается; бот не накладывает знак на свой же выход.
- Альбом (несколько фото/видео, в том числе 1 фото + 1 видео) в личке → каждый файл; в канале — все вложения, оригинал удаляется только если все ушли.
- Профиль без кнопок оплаты.
- На телефоне MAX меню не копится пузырями при переходах текст→текст.
- Стикер в личке → «этот тип не поддерживается».
- `/start` во время «пришлите картинку» выходит в Шаблоны, не требует картинку.

Юнит-уровень: `pytest` (клавиатуры ↔ `ROUTES`, клейм канала, caption личка vs канал, overlay, ffmpeg overlay+concat).

## 10. После v1 (не смешивать)

1. Смоук §9 в клиенте MAX (телефон: меню без лишних пузырей).
2. Биллинг (тарифы, TBank/звёзды, paywall на каналы).
3. Мини-апп / визуальный редактор / motion.
4. Очередь и ретраи, если видео не укладывается в таймаут апдейта.
5. Pin конкретного хвоста на канал (`channels.tail_id`); исходящий альбом одним `payload.photos` вместо N сообщений.
